.. _designs-import:

Import an Existing Design
=========================

:class:`~doetools.ImportDesign` loads an experimental design generated by
another tool from a CSV or Excel file. It exposes the same modelling,
visualisation, optimisation, confirmation, and reporting workflow as designs
generated by *doetools*.

The imported factor columns are selected by the keys of the "factors" mapping.
Other columns in the file are ignored during design initialization.

Importing values in experimental units
--------------------------------------

Define every factor before importing the file:

.. code-block:: python

    from doetools import CategoricalFactor, ContinuousFactor, ImportDesign

    factors = {
        "Temperature": ContinuousFactor(
            n_levels=3,
            lower_bound=20,
            upper_bound=40,
            decimals=1,
        ),
        "Catalyst": CategoricalFactor(
            levels=["C", "A", "B"],
            reference_level="A",
        ),
    }

    design = ImportDesign(
        factors=factors,
        file_path="external_design.csv",
    )

For continuous factors, "lower_bound" and "upper_bound" define the linear
coding scale: they correspond to coded values -1 and 1. The initial "n_levels"
is only provisional for an imported design. After loading the file, *doetools*
replaces "levels", "coded_levels", and "n_levels" with the distinct values
actually observed.

Non-equally-spaced levels
-------------------------

Imported continuous levels do not need to be equally spaced. With coding bounds
20 and 40, the observed values below are coded as follows:

.. list-table::
   :header-rows: 1

   * - Experimental value
     - Coded value
   * - 20
     - -1
   * - 25
     - -0.5
   * - 40
     - 1

The importer applies the coding transformation independently to each observed
value; it does not regenerate the levels with an equally spaced sequence.

The declared bounds represent the -1 and 1 coding points, not necessarily the
minimum and maximum values found in the file. This distinction preserves axial
points in a circumscribed central composite design. For example, values 15.86
and 44.14 with bounds 20 and 40 retain coded values approximately -1.414 and
1.414.

Importing coded values
----------------------

Set "coded=True" when the factor columns already contain coded values:

.. code-block:: python

    design = ImportDesign(
        factors=factors,
        file_path="coded_external_design.xlsx",
        coded=True,
    )

The supplied factor definitions are then used to construct the corresponding
matrix in experimental units. Categorical codes are decoded using the declared
level order, while mixture components are unchanged.

Categorical factors
-------------------

The order passed to :class:`~doetools.CategoricalFactor` determines the numeric
codes and is never inferred or sorted by the importer. Every categorical value
in an uncoded file must occur in the declared "levels". In a coded file, each
value must match one of the factor's generated "coded_levels".

Mixture factors
---------------

Mixture designs can also be imported:

.. code-block:: python

    from doetools import ImportDesign, MixtureFactor

    mixture_factors = {
        "A": MixtureFactor(lower_bound=0.0, upper_bound=1.0),
        "B": MixtureFactor(lower_bound=0.0, upper_bound=1.0),
        "C": MixtureFactor(lower_bound=0.0, upper_bound=1.0),
    }

    mixture_design = ImportDesign(
        factors=mixture_factors,
        file_path="mixture_design.csv",
    )

Each mixture component is checked against its declared bounds, and the mixture
components must sum to 1 in every row.

Validation
----------

Import fails with an explanatory error when:

* the factor mapping is empty or contains unsupported factor objects;
* a factor key does not match a file column;
* a factor column contains missing or non-finite values;
* a continuous or mixture column contains non-numeric data;
* a categorical value or code was not declared;
* mixture values violate their bounds or do not sum to 1.
